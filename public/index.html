🛑 1. Flawed AI Output I Rejected: Application-Level Capacity Checks (TOCTOU)

The AI initially suggested checking if (count < 4) in Node.js before charging payment. I rejected this because under concurrency, two parents read count = 3 simultaneously, both charge cards, and the class is overbooked to 5 students.

-- THE SENIOR CORRECTION (Database Engine Invariant):
UPDATE trial_classes SET confirmed_count = confirmed_count + 1 WHERE id = ? AND confirmed_count < capacity;
🛑 2. Architectural Tradeoff: Optimistic Finalization vs 10-Minute Cart Hold

I rejected 10-minute temporary seat reservations because cart abandonment causes seat hoarding (preventing genuine parents from booking the last slot). Instead, we allow concurrent checkouts: the first payment confirmation secures the seat atomically; the latecomer is immediately compensated with a full automated instant refund ($25.00).
